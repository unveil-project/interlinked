# Regression Testing System

This document describes the regression testing system for the AI/human text classifier in `interlinked`.

## Overview

The regression testing system ensures that changes to the classification algorithm don't inadvertently flip the classification of known examples. This is critical when:

- Adding new signals
- Adjusting signal weights or caps
- Modifying the classification logic
- Changing the bias or threshold values

## Components

### 1. Fixtures Directory (`tests/fixtures/`)

Contains markdown files (typically PR descriptions) that serve as test cases. Each fixture is a real-world example that has been manually verified and labeled.

### 2. Regression Manifest (`tests/fixtures/regression.json`)

A JSON file that maps each fixture to its expected classification:

```json
{
  "version": 1,
  "fixtures": {
    "pr1.md": {
      "label": "ai",
      "reason": "AI-generated: code-span-density, scope-disclaimer, imperative-action signals"
    },
    "pr2.md": {
      "label": "ai",
      "reason": "AI-generated: validation-line, imperative-action, test-reference signals"
    }
  }
}
```

**Fields:**
- `label`: Either `"ai"` or `"human"` - the expected classification
- `reason`: Optional explanation of why this label is correct

### 3. Regression Test Suite (`tests/regression.test.ts`)

Vitest-based test suite that runs the following checks:

1. **Manifest Coverage**: All fixtures in the directory are listed in the manifest
2. **File Existence**: All manifest entries have corresponding fixture files
3. **Classification**: Each fixture is classified according to its label
4. **Probability Validation**: Probability is on the correct side of `AI_THRESHOLD`
5. **Confidence Thresholds**: Confidence scores meet minimum quality standards
6. **Result Structure**: Analysis results have valid structure

### 4. Helper Script (`scripts/add-fixture.ts`)

A CLI tool to easily add new fixtures:

```bash
# Interactive mode - prompts for file, label, and reason
pnpm add-fixture --interactive

# Non-interactive mode
pnpm add-fixture --file ./my-pr.md --label ai --reason "Generated by Claude Code"
pnpm add-fixture --file ./my-pr.md --label human --reason "Written by maintainer"
```

## Usage

### Adding Your First Human Example

Currently, all fixtures are AI-generated. To add a human-written example:

1. Create a markdown file with a human-written PR description:
   ```bash
   echo "This is a human-written PR description that fixes a bug I found." > human-pr.md
   ```

2. Add it using the helper script:
   ```bash
   pnpm add-fixture --file human-pr.md --label human --reason "Human-written with natural language"
   ```

3. Verify it passes:
   ```bash
   pnpm test:regression
   ```

### Workflow for Making Changes

When modifying the classification logic:

1. **Before making changes**: Run tests to establish baseline
   ```bash
   pnpm test:regression
   ```

2. **Make your changes** to `src/index.ts`

3. **Run tests again**:
   ```bash
   pnpm test:regression
   ```

4. **If tests fail**:
   - If the failure is expected (you intentionally changed behavior), update the manifest
   - If the failure is unexpected, reconsider your changes

5. **Add new test cases** for edge cases your changes address

### Updating the Manifest

When you intentionally change the classification behavior and some fixtures now classify differently, update `regression.json` to reflect the new expected labels.

```json
{
  "fixtures": {
    "pr1.md": {
      "label": "ai",
      "reason": "Now correctly classified as AI after signal weight adjustment"
    }
  }
}
```

## Test Commands

| Command | Description |
|---------|-------------|
| `pnpm test:regression` | Run only regression tests |
| `pnpm test` | Run all tests (including regression) |
| `pnpm add-fixture --interactive` | Add a new fixture interactively |
| `pnpm add-fixture --file <path> --label <ai|human>` | Add a new fixture non-interactively |

## Configuration Options

The regression tests have a configurable minimum confidence threshold (currently 0.55). You can adjust this in `tests/regression.test.ts`:

```typescript
const MIN_CONFIDENCE = 0.55; // Adjust as needed
```

## Best Practices

1. **Diverse Examples**: Include a variety of AI and human examples
2. **Edge Cases**: Add fixtures that test boundary conditions
3. **Documentation**: Always include a `reason` in the manifest for each fixture
4. **Real-World**: Use actual PR descriptions, not synthetic examples
5. **Balance**: Maintain a roughly equal number of AI and human examples
6. **Review**: Have others review the label assignments for accuracy

## Understanding the Classifier

The classifier uses a logistic regression approach with signals that have positive (AI-leaning) or negative (human-leaning) weights. Key metrics:

- **Verdict**: `"ai"` or `"human"` - the final classification
- **Probability**: 0-1, probability the text is AI-generated
- **Confidence**: 0.5-1, confidence in the verdict (1 - probability for human)
- **Threshold**: Currently 0.5 - probability >= threshold means "ai"

Each signal contributes to a logit score, which is then converted to probability via the sigmoid function.

## Example: Adding a Human Fixture

Let's say you have a human-written PR description in `my-human-pr.md`:

```markdown
Fixes #123: Add missing error handling

I noticed that when the API returns an error, we don't handle it properly.
This PR adds error handling and tests for it.
```

Add it to the test suite:

```bash
pnpm add-fixture --file my-human-pr.md --label human --reason "Human-written with first-person perspective and natural language"
```

Then verify:

```bash
pnpm test:regression
```

If this fails because the classifier incorrectly identifies it as AI, you may need to:
1. Adjust signal weights
2. Add new signals that detect human characteristics
3. Accept that this is a misclassification and adjust accordingly

## Continuous Integration

The regression tests should be part of your CI pipeline to prevent accidental regressions. Add to your CI configuration:

```yaml
- name: Run regression tests
  run: pnpm test:regression
```

This ensures that any PR that changes classification behavior must intentionally update the manifest to reflect the new expected behavior.
